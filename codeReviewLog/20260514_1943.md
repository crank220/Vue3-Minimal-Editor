# Code Review Log - 2026-05-14 19:43

## 审查范围

- 项目：`hd-text-editor`
- 技术栈：Vue 3 + Vite + 原生 CSS + contenteditable + Canvas
- 假设边界：组件会作为 npm 包被业务方引入，`html` 与 `annotations` 可能来自外部输入，不应默认可信。

## 原始发现与修复记录

### 1. 外部 HTML 未净化

- 严重等级：严重
- 位置：`src/components/RichTextEditor.vue`、`src/components/PreviewPanel.vue`
- 风险：外部 `html` 直接进入 `innerHTML` / `v-html` / tokenization 链路，可能产生 XSS。
- 修复：
  - 新增 `src/utils/sanitizeHtml.js`。
  - 仅允许 `span` 和 `br`。
  - 仅允许受控内联样式属性。
  - 移除 `on*` 事件、危险标签、危险 CSS 值、未知属性。
  - `props.html`、contenteditable 输入、预览渲染、单行 tokenization 全部统一使用净化后的 HTML。

### 2. 多实例共享选区状态

- 严重等级：主要
- 位置：`src/composables/useSelection.js`
- 风险：模块级 `savedRange` 会被多个编辑器实例共享，可能导致跨实例误改。
- 修复：
  - 新增 `createSelectionStore()`。
  - 每个 `RichTextEditor` 实例创建独立 selection store。
  - `getRange(root)` 会校验 Range 仍属于当前编辑器根节点，不属于时自动清空。

### 3. 编辑区宽高和 Canvas 缺少安全预算

- 严重等级：主要
- 位置：`src/composables/useStyle.js`、`src/components/RichTextEditor.vue`、`src/components/PreviewPanel.vue`
- 风险：极端宽高会创建超大 DOM 和 Canvas，导致卡死或崩溃。
- 修复：
  - 新增 `MIN_EDITOR_DIMENSION`、`MAX_EDITOR_DIMENSION`、`MAX_EDITOR_PADDING`、`MAX_CANVAS_PIXELS`。
  - 编辑区宽高限制为 `120 - 4096`。
  - padding 限制为 `0 - 2048`。
  - Canvas 创建前检查像素预算，超过 `16777216` 像素时抛出可见错误。

### 4. 发布 registry 使用 HTTP 且脚本命名含混

- 严重等级：次要
- 位置：`package.json`、`README.md`
- 风险：HTTP registry 明文传输；`publish` 脚本容易和 npm 生命周期混淆。
- 修复：
  - `publish` 改为 `publish:internal`。
  - registry 改为 `https://192.168.90.222:66/`。
  - README 发布命令同步更新。

### 5. 缺少 lint、单测与浏览器回归测试

- 严重等级：次要
- 位置：`package.json`、测试配置
- 风险：Range、Selection、DOM 归一化、Canvas 导出属于高回归风险链路。
- 修复：
  - 新增 ESLint 配置与 `npm run lint`。
  - 新增 Vitest + jsdom 单测与 `npm run test:unit`。
  - 新增 Playwright E2E 与 `npm run test:e2e`。
  - 新增 `npm run test:all` 聚合脚本。
  - 单测覆盖 HTML 净化、选区隔离、DOM 归一化。
  - E2E 覆盖外部 HTML 注入净化和 PNG 截图链路。

### 6. 未使用函数增加维护成本

- 严重等级：建议
- 位置：`src/components/PreviewPanel.vue`
- 风险：未使用的排版/调试函数增加阅读成本。
- 修复：
  - 删除 `renderTokens`、`isMeasureOverflowing`、`renderLayoutToCanvas`、`getHorizontalOffset` 等当前无调用函数。
