## 原始发现与修复记录

### 1. `text-shadow` 无法兼容逗号颜色函数

- 严重等级：次要
- 位置：`src/utils/sanitizeHtml.js`、`src/components/PreviewPanel.vue`
- 风险：`rgb(0, 0, 0)` / `rgba(0, 0, 0, 0.5)` 会被普通逗号拆分破坏，导致合法阴影在 HTML 清洗或 Canvas 导出时丢失。
- 修复：
  - 新增 `src/utils/cssTextShadow.js`，提供括号感知的 CSS 列表拆分、tokenize 与 `parseCssTextShadow()`。
  - `sanitizeStyleText()` 使用共享解析器，并允许标准逗号式 `rgb()` / `rgba()` 与空格式颜色函数。
  - Canvas 导出侧的 `parseTextShadows()` 改为复用共享解析器，兼容 `x y blur color` 与 `color x y blur`。
  - 新增 `tests/unit/cssTextShadow.test.js` 与 `sanitizeHtml` 覆盖用例。

### 2. annotations 公共工厂只归一化 style 分区

- 严重等级：次要
- 位置：`src/composables/useStyle.js`、`src/components/RichTextEditor.vue`
- 风险：外部传入极端 `editorBox` / `preview` 值时，`createTextEditorAnnotations()` 返回值和组件运行时约束不一致。
- 修复：
  - 新增 `normalizeEditorBox()`，统一约束宽高 `120px ~ 4096px` 与 padding `0px ~ 2048px`。
  - 新增 `normalizePreviewConfig()`，统一约束模式枚举、翻页时长、停留时长、切片宽度、单行速度和无缝滚动布尔值。
  - `createTextEditorAnnotations()` 的 `style / editorBox / preview` 三个分区全部接入 schema 归一化。
  - `RichTextEditor` 的 `previewState` watcher 复用 `normalizePreviewConfig()`，避免运行时规则继续分叉。
  - `normalizeTextStyle()` 改为严格解析 `"true"` / `"false"` 字符串，避免 `"false"` 被 `Boolean()` 误判为 `true`。

### 3. 单行切片展示和 README 规则不一致

- 严重等级：建议
- 位置：`src/components/PreviewPanel.vue`、`README.md`
- 风险：界面展示的切片数量按固定 `8096px` 计算，README 仍写单张切片上限 `65536px`，与实际 `8192px` 画布单轴保护不一致。
- 修复：
  - `singleSliceCount` 改为按当前有效 `Cut image width` 计算。
  - 预览说明改为展示单行总宽度 `65536px` 与单张 PNG 切片上限 `8192px`。
  - README 同步编辑区宽高、padding、单张切片上限和切片粒度说明。

## 追加复审与修复记录

### 4. Canvas 导出未体现 `text-shadow` blur

- 严重等级：次要
- 位置：`src/components/PreviewPanel.vue`
- 风险：HTML 清洗会保留 `text-shadow` 的 blur 值，但 PNG 导出只按 `x/y/color` 绘制硬阴影，导致 DOM 预览和导出图在模糊阴影上不一致。
- 修复：
  - `parseTextShadows()` 保留并归一化 `blur`。
  - 新增 `drawTextShadow()`，对 blur 大于 0 的阴影使用 Canvas `shadowBlur`、`shadowOffsetX`、`shadowOffsetY` 绘制。
  - 使用隐藏源文字偏移绘制方式，避免把阴影源文字额外画到导出图上。
  - 新增 E2E 用例验证带 blur 的红色阴影能进入 PNG 输出。

### 5. annotations schema 入口对 `null` / 非对象输入不够稳健

- 严重等级：次要
- 位置：`src/composables/useStyle.js`
- 风险：外部受控方如果传入 `null`、数组等非普通对象，`createTextEditorAnnotations()` / `normalizeTextStyle()` 等入口会读取属性时报错。
- 修复：
  - 新增 `toPlainObject()`，在公共 schema 入口把 `null`、数组和非对象输入回退为 `{}`。
  - `createTextEditorAnnotations()`、`normalizeTextStyle()`、`normalizeEditorBox()`、`normalizePreviewConfig()` 全部接入空值保护。
  - 新增单元测试覆盖 `createTextEditorAnnotations(null)`、数组输入和三个 normalize 入口的 `null` 回退。

## 第二次追加复审与修复记录

### 6. 长单行切片可能泄漏 blur 阴影源文字

- 严重等级：次要
- 位置：`src/components/PreviewPanel.vue`
- 风险：上一轮 blur 阴影实现用 `x - hiddenOffset` 隐藏源文字。单行切片会遍历整条长文本并用 clip 裁剪，当前切片右侧的远处字符可能被这个反向偏移重新画进可见区，污染第一张 PNG。
- 修复：
  - `drawTextShadow()` 改为使用固定离屏源坐标 `hiddenSourceX`。
  - `shadowOffsetX` 改为按目标坐标动态计算，确保阴影落在 `x + shadow.x`，而源文字始终位于画布左侧离屏位置。
  - 新增 E2E 用例 `does not leak off-slice blurred shadow source glyphs`，构造长单行文本并断言第一张切片没有来自后续字符的蓝色污染像素。
